# Pull request description

## Sections

1. Summary: what the change does, in two sentences.
2. Why: the problem it solves, with a link to the ticket.
3. How to test: steps that a reviewer can follow.
4. Risks: what could break, and how you checked it.

Keep it short. Put details in the code comments, not here.
